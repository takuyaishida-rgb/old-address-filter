# 郵便番号・旧住所フィルター — プロダクト定義

最終更新: 2026-07-30

## 1. これは何か

住所リスト（Excel／CSV）を投入すると、**郵便番号を付与し、旧住所・表記の異常をフラグして返す**ブラウザ完結型のツール。
ファイルはサーバーに送信せず、すべてブラウザ内で処理する。

公開URL: https://takuyaishida-rgb.github.io/old-address-filter/
GitHub Pages（公開リポジトリ）で配信しており、**URLを知っていれば社外の誰でも閲覧・利用できる**。

## 2. 解く問題

| 現場の問題 | 従来のやり方 | 本ツール |
|---|---|---|
| 送付先リストに郵便番号がない | 日本郵政サイトで1件ずつ検索 | 住所列から一括付与 |
| 郵便番号と住所が食い違う | 目視 | マスター突合でフラグ |
| 相続・古い謄本由来の住所が現行と違う | 気づけない | 消滅市郡・旧字体・漢数字番地を検出 |
| 同一物件が表記ゆれで重複 | 手作業 | 正規化キーで重複グループ化 |

想定ユーザー: 自社営業・データ作成チーム、および取引先（URLを渡して自走してもらう）。

## 3. 機能定義（2系統 + 拡張）

### 入力の指定
- **複数シートのブック**はシートを選択できる。処理対象以外のシートも出力に保持する（値のみ・書式は保持されない）
- **ヘッダー行**は先頭20行から自動推定し（値が2つ以上入る最初の行）、選択で変更できる。ヘッダー行より上の行はそのまま残す

### A. 郵便番号（Postal）

住所文字列から郵便番号を決める処理は `index.html` の**リゾルバ**に集約している（`resolveZip` / `resolveZipDeep`）。設計は次の4点。

1. 段階を明示し、各段は「決まったか／決まらなかったか」だけを返す
2. 候補が複数出たら **確度（precision）→ 一致した町域名の長さ** で機械的に選ぶ。同点なら決めない
3. 区・郡は「その市区町村にその町域が実在するか」でしか決めない（旧市町村マップの代表郵便番号から区名を推測しない。存在しない住所を作るため）
4. 決められないものは埋めず、理由を返す

**確度**: `4=小字` / `3=町域` / `2=市区町村（掲載外・町域なし）` / `0=未確定`

#### 段階

| 段階 | 内容 |
|---|---|
| 正規化 | 異体字の統一（俱→倶 など）、`ヶ`→`ケ`、全角数字→半角。**1文字→1文字の置換のみ**（文字数が変わると住所内の位置がずれる） |
| 市区町村の特定 | ①名称の前方一致（最長優先）②政令市で区が無い場合は全区を候補にする ③郡が省略・誤記された場合は町村名で探す |
| 町域の照合 | 表記ゆれを吸収した候補列で前方一致。当たらなければ**部分一致**（合併で町域名に旧町村名が前置されるケース。一意のときだけ採用） |
| 複数候補の一意化 | 小字 → 丁目の範囲 → 方角 → 小字なし候補 → 「その他」の順で絞る |
| 市区町村レベル | 町域の登録が無い市区町村は代表番号が正解。登録があるのに該当が無い場合は「以下に掲載がない場合」が正解 |
| 旧住所からの再解決 | 旧市町村マップで現行の市区町村に置き換えて取り直す。旧町村名が町域名の一部として残る形も試し、整合を検証してから採用する |
| 候補の選択 | 確度→町域名の長さ。同点が複数なら「区が特定できない」等として未確定 |

#### 表記ゆれの吸収

- 全角数字→半角、先頭の「字」「大字」の読み飛ばし、`ヶ`↔`ケ`、重複した「町」の除去
- `N条` `N丁目` は算用数字↔漢数字の**両方向**を試す（マスターは「南一条西」「ニセコひらふ一条」の一方で、旭川市は「７条通」のように算用数字。1〜99に対応）
- 「大字○○村字△△」を詰めた形（合併後の町域名は村・字を挟まない）
- 異体字は入力とマスターの**両側**を同じ字に寄せる。マスター側にも異体字が実在する（塚 U+FA10 が1,311件、舘165件など）

#### 複数候補の一意化の判断材料

同じ町域名に複数の郵便番号があるのは、小字・丁目・方角で分かれているため（1,017町域）。

- **小字**: KEN_ALL の町域欄の括弧内（「香良洲町（稲葉）」）を `koaza` として保持（5,096件）
- **丁目の範囲**: 「南一条西（１～１９丁目）」を `chome` として保持（220件）
- **方角**: 「南郷通（南）」を `side` として保持（16件）
- **「その他」**（列挙外の受け皿）は、住所側に判断材料がある場合か、列挙が小字ベースでない場合に限って採用する
  - 採用: 「鳴海町字坊主山」（小字が書かれていて列挙に無い）／「潮江二丁目1番28」（列挙は1丁目1番・5丁目1番のみ）
  - 却下: 「香良洲町3032-1」（列挙が小字別で、住所に小字が無いので判断できない）

#### マスター生成上の注意

1つの郵便番号が複数の町域をカバーすることがある（例: 喜茂別町の上尻別と鈴川が同じ044-0451）。町域名で上書きすると逆引きできなくなるため `alt` に退避している（全国3,623町域）。

#### 未確定の扱い

一意に決まらない場合は**推定値で埋めない**。空欄＋理由を返す。理由は次の系統に分かれる。

| 系統 | 返す理由 |
|---|---|
| データの不完全性 | 住所が空欄／町域名の欠落（「倶知安町字189-16」） |
| 判断材料の不足 | `小字・丁目で郵便番号が分かれる町域です（候補N件： …）` |
| 区が決まらない | `複数の区に同じ町域があり区を特定できません（中央区・南区）` |
| 市区町村が引けない | 旧市町村マップに未収録の町村（岡山県苫田郡上斎原村など） |
| マスターの範囲外 | 大口事業所個別番号は未収録（対応予定） |

詳細オプション「町域を特定できない行を市区町村の代表番号で埋める」（既定オフ）で代表番号での補完を選べる。

#### 回帰テスト

`tests/resolver-cases.js`（Node.js）。実住所37ケースで、上記すべての段階と「埋めてはいけないケース」を検証する。**ロジックを触ったら必ず通す。**

```bash
node tests/resolver-cases.js
```

### B. 旧住所（Legacy）
- **B-1 検出**: 消滅郡名・消滅市名・消滅区名（東京35区）・消滅地名・旧字体・漢数字番地・カタカナ「ノ」区切り
- **B-2 現行住所の推定**: 旧市町村マップ（約2,500件）で現行住所を別列に追記（元の住所列は上書きしない）

### C. 拡張（オプション）
- **C-1 緯度経度・地図URL** の付与
- **C-2 重複検出**: 表記ゆれ正規化キーで同一物件をグループ化

## 4. 出力仕様

元の列は一切変更せず、右端に追記する。

| 列 | 条件 |
|---|---|
| 郵便番号（推定） / 推定レベル / 未確定理由 | A-1 ON |
| 郵便番号突合結果 | A-2 ON（既存郵便番号列あり） |
| 旧住所フラグ / 判定理由 | B-1 ON |
| 現行住所（推定） | B-2 ON |
| 緯度 / 経度 / 地理レベル / マップURL | C-1 ON |
| 正規化住所 / 重複ステータス / 重複グループID | C-2 ON |

## 5. 原則

1. **推定と事実を混ぜない** — 推定列は列名に「（推定）」を入れ、確度（町域／市区町村／不明）を必ず併記する
2. **黙って埋めない** — 確度が落ちる代替値で穴埋めせず、空欄＋理由で返す
3. **元データを壊さない** — 上書き・並び替え・行削除をしない。追記のみ
4. **ブラウザ内処理** — アップロードなし。取引先に渡せる前提を崩さない
5. **絵文字を使わない** — UI・出力ともアイコンはSVG、ラベルは日本語テキスト

## 6. データソース

| データ | 出所 | 件数 |
|---|---|---|
| 郵便番号マスター | 日本郵便 ken_all | 約12万 |
| 旧市町村マップ | NAreaCode（MIT）＋ ken_all | 約2,500 |
| 地理データ | geolonia 住所データ | 約12MB |

## 7. 対応予定

- **大口事業所個別番号**（企業専用の郵便番号）: 日本郵便 `jigyosyo.zip` から生成し、法人名でも郵便番号を引けるようにする
- **旧市町村マップの拡充**: 平成合併前に消滅した町村（例: 岡山県苫田郡上斎原村、埼玉県入間郡鶴ヶ島町）が未収録

### 採用しなかった案

**「郡が一致し、その郡に残る市区町村が1つならそこに寄せる」**: 実データで4件の誤りを生んだため撤回した。旧町村が郡から抜けて別の市になっている場合（中巨摩郡竜王町→甲斐市、高座郡綾瀬町→綾瀬市）に、郡に残る無関係な町（昭和町・寒川町）を掴む。

## 8. 運用上の注意

`data/` の生成物を再生成したら、`index.html` の `DATA_VERSION` を必ず更新する。ブラウザが約9MBの旧JSONをキャッシュし続け、更新が反映されないため。

## 9. スコープ外

- 番地レベルのジオコーディング（町域重心まで）
- 建物名・部屋番号の正規化（住所本体と分離するのみ）
- 住民票・登記の名寄せ、氏名の異体字判定（別ツール）
