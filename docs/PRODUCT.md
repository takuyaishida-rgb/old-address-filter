# 郵便番号・旧住所フィルター — プロダクト定義

最終更新: 2026-07-30

## 1. これは何か

住所リスト（Excel／CSV）を投入すると、**郵便番号を付与し、旧住所・表記の異常をフラグして返す**ブラウザ完結型のツール。
ファイルはサーバーに送信せず、すべてブラウザ内で処理する。

公開URL: https://takuyaishida-rgb.github.io/old-address-filter/
GitHub Pages（公開リポジトリ）で配信しており、**URLを知っていれば社外の誰でも閲覧・利用できる**。

## 2. 解く問題

| 現場の問題 | 従来のやり方 | 本ツール |
|---|---|---|
| 送付先リストに郵便番号がない | 日本郵政サイトで1件ずつ検索 | 住所列から一括付与 |
| 郵便番号と住所が食い違う | 目視 | マスター突合でフラグ |
| 相続・古い謄本由来の住所が現行と違う | 気づけない | 消滅市郡・旧字体・漢数字番地を検出 |
| 同一物件が表記ゆれで重複 | 手作業 | 正規化キーで重複グループ化 |

想定ユーザー: 自社営業・データ作成チーム、および取引先（URLを渡して自走してもらう）。

## 3. 機能定義（2系統 + 拡張）

### 入力の指定
- **複数シートのブック**はシートを選択できる。処理対象以外のシートも出力に保持する（値のみ・書式は保持されない）
- **ヘッダー行**は先頭20行から自動推定し（値が2つ以上入る最初の行）、選択で変更できる。ヘッダー行より上の行はそのまま残す

### A. 郵便番号（Postal）
- **A-0 住所の解決順**: 完全一致ではなく次の順で解決する
  1. `都道府県 → 市区町村 → 町域` の最長一致（表記ゆれ・異体字を吸収）
  2. 町域が当たらない場合、**含む町域がちょうど1つ**なら採用（合併で町域名に旧町村名が前置されるケース。例:「岩見沢市字茂世丑」→「岩見沢市栗沢町茂世丑」）
  3. 政令市で区が無い／区が誤っている場合、**同じ市の全区から町域を探し一意なら確定**（例:「千葉市末広町」→ 中央区末広、旧住所変換で入った誤った区も訂正）
  4. 郡が省略・誤記されている場合、`〇〇郡△△町` 形式の町村名で照合（例:「足柄上部大井町」→ 足柄上郡大井町）
  5. どれも決まらなければ空欄＋理由
- **A-1 付与**: 住所列から郵便番号を推定して列追加。`都道府県 → 市区町村 → 町域` の最長一致
- **A-1a 表記ゆれの吸収**: 全角数字→半角、先頭の「字」「大字」の読み飛ばし、`N条`の算用数字→漢数字（マスターは「ニセコひらふ一条」「北四十二条東」形式。1〜99に対応。実データ上の最大は51条）、`ヶ`↔`ケ`、重複した「町」の除去
- **A-1b 異体字の吸収**: 地名の異体字を入力とマスターの**両側**で同じ字に寄せてから照合する（例: 入力「**俱**知安町」U+4FF1 と 日本郵便「**倶**知安町」U+5036）。マスター側にも異体字は実在する（塚1,311件・舘165件など）ため片側だけの正規化では当たらない。対応は1文字→1文字の置換に限る（文字数が変わると住所内の位置がずれるため）
- **A-2 突合**: 既存の郵便番号列とマスターを突合し、不一致・存在しない番号をフラグ
- **A-3 未確定の扱い**: 一意に決まらない場合は**推定値で埋めない**。空欄＋理由を返す。未確定は次の4系統に分かれる

| 系統 | 例・返す理由 |
|---|---|
| データの不完全性 | 住所が空欄／町域名の欠落（「倶知安町字189-16」）／旧住所で現行マスターに町域がない |
| 表記の揺れ | 政令市の区が省略（マスター上171区）／京都の通り名など → `住所から市区町村を特定できず` |
| マスターの多義性 | 同一町域名に複数の郵便番号（小字で分岐。1,017町域）。住所に小字があれば一意に決まる（774町域が判別可能）。決まらない場合は `小字で郵便番号が分かれる町域（候補N件： 稲葉・小松…）` と候補を提示し、**片方を黙って採用しない** |
| マスターの範囲外 | 大口事業所個別番号は未収録（jigyosyo.zip・対応予定） |

小字は KEN_ALL の町域欄の括弧内（例:「香良洲町（稲葉）」）にあり、`build_postal_master.py` が `koaza` として保持する（5,096件）。列挙外を意味する「その他」は判別に使わない。

町域の登録が無い市区町村（1,769件）は代表番号が唯一の正解なので、`市区町村（町域なし）` として**確定値で付与**する。町域があるのに一致しなかった場合のみ未確定とし、詳細オプション「町域を特定できない行を市区町村の代表番号で埋める」（既定オフ）で代表番号での補完を選べる。

### B. 旧住所（Legacy）
- **B-1 検出**: 消滅郡名・消滅市名・消滅区名（東京35区）・消滅地名・旧字体・漢数字番地・カタカナ「ノ」区切り
- **B-2 現行住所の推定**: 旧市町村マップ（約2,500件）で現行住所を別列に追記（元の住所列は上書きしない）

### C. 拡張（オプション）
- **C-1 緯度経度・地図URL** の付与
- **C-2 重複検出**: 表記ゆれ正規化キーで同一物件をグループ化

## 4. 出力仕様

元の列は一切変更せず、右端に追記する。

| 列 | 条件 |
|---|---|
| 郵便番号（推定） / 推定レベル / 未確定理由 | A-1 ON |
| 郵便番号突合結果 | A-2 ON（既存郵便番号列あり） |
| 旧住所フラグ / 判定理由 | B-1 ON |
| 現行住所（推定） | B-2 ON |
| 緯度 / 経度 / 地理レベル / マップURL | C-1 ON |
| 正規化住所 / 重複ステータス / 重複グループID | C-2 ON |

## 5. 原則

1. **推定と事実を混ぜない** — 推定列は列名に「（推定）」を入れ、確度（町域／市区町村／不明）を必ず併記する
2. **黙って埋めない** — 確度が落ちる代替値で穴埋めせず、空欄＋理由で返す
3. **元データを壊さない** — 上書き・並び替え・行削除をしない。追記のみ
4. **ブラウザ内処理** — アップロードなし。取引先に渡せる前提を崩さない
5. **絵文字を使わない** — UI・出力ともアイコンはSVG、ラベルは日本語テキスト

## 6. データソース

| データ | 出所 | 件数 |
|---|---|---|
| 郵便番号マスター | 日本郵便 ken_all | 約12万 |
| 旧市町村マップ | NAreaCode（MIT）＋ ken_all | 約2,500 |
| 地理データ | geolonia 住所データ | 約12MB |

## 7. 対応予定

- **大口事業所個別番号**（企業専用の郵便番号）: 日本郵便 `jigyosyo.zip` から生成し、法人名でも郵便番号を引けるようにする
- **丁目で郵便番号が分かれる町域**: KEN_ALL の「南一条西（２０〜２８丁目）」形式の範囲指定を解釈する（実データで最大の残存要因。1,061件の検証では9件が該当）
- **大字を含む町域名**の照合（「枝幸町大字歌登村字上幌別六線」など）

## 8. 運用上の注意

`data/` の生成物を再生成したら、`index.html` の `DATA_VERSION` を必ず更新する。ブラウザが約9MBの旧JSONをキャッシュし続け、更新が反映されないため。

## 9. スコープ外

- 番地レベルのジオコーディング（町域重心まで）
- 建物名・部屋番号の正規化（住所本体と分離するのみ）
- 住民票・登記の名寄せ、氏名の異体字判定（別ツール）
