# 郵便番号・旧住所フィルター

住所リスト（Excel／CSV）に**郵便番号を付与**し、**旧住所や表記の異常をフラグ**するブラウザ完結型ツール。

**[今すぐ使う](https://takuyaishida-rgb.github.io/old-address-filter/)**

- インストール不要 — ブラウザで開くだけ
- ファイルはサーバーに送信されない — 処理はすべてブラウザ内
- 日本郵便の全国マスター約12万件、旧市町村マップ約2,500件を同梱
- 元の列は変更しない。追記する列のうち「郵便番号（推定）」は既存の郵便番号列の右隣（無ければ住所列の右隣）、「補正後住所」「補正内容」は住所列の右隣に並べ、元と変更後を見比べやすくする。その他の列は右端に追記

## 使い方

1. Excel／CSVをドロップ（複数シートのブックはシートを選択。ヘッダー行は自動推定・変更可）
2. 処理内容を選ぶ（郵便番号を付ける／旧住所を判定する／両方）→ 住所列を指定
3. 実行 → 結果を確認し、処理済みファイルをダウンロード

対象シート以外のシートも出力に保持されるが、書式は保持されず値のみになる。

## A. 郵便番号

| 機能 | 内容 |
|---|---|
| 付与 | 住所を `都道府県 → 市区町村 → 町域` で最長一致させて推定 |
| 表記ゆれの吸収 | 全角数字→半角、「字」「大字」の読み飛ばし、`N条`の算用数字→漢数字（例:「ニセコひらふ1条」→「ニセコひらふ一条」／1〜99対応）、`ヶ`↔`ケ` |
| 異体字の吸収 | 入力とマスターの両側を同じ字に寄せて照合（例:「俱知安町」U+4FF1 と「倶知安町」U+5036、髙/高、舘/館、濱/浜、邊/辺） |
| 番号の品質チェック | 既存の郵便番号列を指定すると、元リストの番号付けの品質を確認する（存在しない番号・市区町村の食い違いは要対応。仮番号・区の食い違いは未確定として情報表示）。**番号は住所から日本郵便データを引いて付けた派生値なので、住所が旧か現行かの根拠にも、住所を直す根拠にも使わない** |
| 仮番号 | 下4桁`0000`（市区町村の代表＝町域未確定）は「元リストの番号付けが町域まで届いていない」という品質情報。住所から町域が引ければ推定番号を併記 |
| 区の食い違い | 住所の区と番号の区が異なる場合は品質情報として表示（どちらが正しいかは番号からは言えない）。旧区の判定は住所の文字列から行う（下記 B-2） |
| 旧市町村名の住所 | 現行の市区町村名と比べず、「照合対象外」と表示（旧住所かどうかは旧住所フラグ列で判定） |
| 未確定の扱い | 一意に決まらない場合は**空欄＋理由**を返し、推定値で埋めない |
| 旧「村」の大字 | 旧村が市に編入された住所で町域が決まらないとき、大字名に「町」を足した町域が実在すれば採る（例: 新治郡上大津村神立→土浦市神立町）。確度Cとして出す |
| 県名が無い住所 | 全県を調べて比べる。町域まで当たる県が1つならそれを採用し、同点が複数県にあれば「都道府県が特定できない」（最初に当たった県で確定しない） |

未確定の理由は4系統ある。

| 系統 | 内容 |
|---|---|
| データの不完全性 | 住所が空欄、町域名の欠落、旧住所で現行マスターに町域がない |
| 表記の揺れ | 政令市の区が省略されている（例:「静岡市追手町」）など |
| マスターの多義性 | 同一町域名に複数の郵便番号がある（小字で分岐。1,017町域）。住所に小字があれば一意に決まり、無ければ候補を提示して未確定にする |
| マスターの範囲外 | 大口事業所個別番号は未収録（対応予定） |

小字は KEN_ALL の括弧内表記（「香良洲町（稲葉）」）から取り込んでいる。「津市香良洲町稲葉2000」は514-0311で確定、「津市香良洲町3032-1」は候補10件を提示して未確定。

町域の登録が無い市区町村は代表番号が唯一の正解なので確定値で付与する。町域があるのに一致しなかった行は、詳細オプション「町域を特定できない行を市区町村の代表番号で埋める」（既定オフ）で補完できる。

出力列: `郵便番号（推定）` / `推定レベル`（町域・市区町村・不明）/ `未確定理由` / `郵便番号突合結果`

## B. 旧住所

| # | 検出パターン | 例 |
|---|---|---|
| 1 | 消滅郡名 | 橘樹郡、稗貫郡、南魚沼郡 |
| 2 | 消滅市名 | 浦和市、大宮市、水沢市 |
| 3 | 消滅区名（東京35区） | 蒲田区、小石川区、神田区 |
| 4 | 消滅地名（町村） | 津久井町、岡部町、城山町 |
| 4' | 旧市町村マップの町村（市区町村の位置に出現したもののみ） | 野々市町、湯田町 |
| 4'' | 旧区（政令市の区の再編。下記 B-2） | 高津区宮崎→宮前区、緑区さつきが丘→青葉区、浜松市中区→中央区 |
| 5 | 旧字体 | 國、縣、區、濱、澤 |
| 6 | カタカナ「ノ」区切り | 1ノ2ノ4 |

旧住所は**補正後住所**で現行の住所に直す（段階合併のチェーン解決に対応）。

番地・丁目の漢数字（壱弐参・〇を含む）は旧住所とは判定せず、別列に半角数字へ変換する（下記）。

出力列: `旧住所フラグ` / `判定理由`（現行住所は下記「補正後住所」）

### B-2. 旧区の判定（郵便番号は使わない）

住所の区に町域が無く、同じ市の別の区に同じ町域がある場合に旧区の可能性として扱う。判断材料は住所の文字列と日本郵便マスターの町域だけで、既存の郵便番号は使わない。

| 確度 | 条件 | 動作 |
|---|---|---|
| B | 区再編表（`WARD_REORG`）に「旧区→その区」があり、その区に町域が実在 | 旧区として要対応。補正後住所で区を直し、郵便番号も直した住所で取り直す |
| C | 別の区に町域はあるが、再編表に裏付けが無い | 直さず、未確定として候補の区を表示 |

- 区名そのものが現行に無い場合（浜松市中区など）も、再編表の後継区に町域が実在するかで判定する。
- 旧市が政令市の区に分かれた場合（浦和市・大宮市など）は、許容区表（`OLD_CITY_WARDS`）の区の中だけで町域を探す。無関係な区（浦和市本町→岩槻区）は選ばない。
- 再編表・許容区表は人手で保守する（`index.html` 内）。載っていない旧区は確度Cになる。

### B-3. 確度（A〜E）

出力の `確度` / `確度の理由` 列。宛名の住所をどこまで機械的に信用してよいかを示す。判定に郵便番号は使わない。番地は常に未検証（住居表示の実施などで番地体系が変わった住所は直せない）。

| 確度 | 意味 | 使い方 |
|---|---|---|
| A | 原文の市区町村・町域が現行マスターにそのまま一致 | そのまま使える |
| B | 変遷表（旧市町村・区再編表・東京35区）に基づいて自動補正し、変換先で町域が一致 | 補正後住所を使える（補正内容を併記） |
| C | 実在性だけで決めたもの（区・郡の補完、部分一致、他県にも同名の住所がある県名なし、再編表に裏付けの無い旧区候補） | 宛名に使えるが要確認 |
| D | 市区町村までしか決まらない（掲載外・町域なし） | 人手で確認 |
| E | 判定できない・矛盾（不明、区や県が決まらない、町域が複数候補、旧住所と判定したのに直せない） | 人手で確認 |

## C. 拡張オプション

- **補正後住所／補正内容**（既定オン）— 分かっている誤りを直した住所を追記し、何を直したかを併記する。直す内容は次の2つ（住所の文字列だけから判定し、郵便番号は使わない）。
  - 旧市町村名を現行に変換（浦和市→さいたま市緑区、久居市新町→津市久居新町）
  - 町域が部分一致でしか決まらなかった旧住所は、町域まで直さず市区町村名だけ現行にする（町域は原文のまま・要確認）。田無市本町→「西東京市田無町田無本町」のような実在しない住所を作らないため
  - 番地・丁目の漢数字（壱弐参・〇を含む）と全角英数字を半角にする（「七壱〇弐番地の壱」→「7102番地の1」）。地名の漢数字（三ツ井・五番町・十日市）は変換しない
- **緯度経度・地図URL** — 町域重心または市区町村重心（geolonia 由来。約12MBを追加読み込み）
- **重複検出** — 表記ゆれを正規化して同一物件をグループ化（`代表` / `重複` / `単独`）

## 結果の見方

| 区分 | 意味 |
|---|---|
| 要対応 | 旧住所と判定、または郵便番号が住所と不一致 |
| 未確定 | 一意に決まらなかった。理由は列に出る |
| 問題なし | 上記いずれにも該当しない |

## データソース・更新

| データ | 出所 | 生成スクリプト |
|---|---|---|
| 郵便番号マスター（約12万件） | 日本郵便 ken_all | `scripts/build_postal_master.py` |
| 旧市町村マップ（約2,500件） | [NAreaCode](https://github.com/timej/NAreaCode)（MIT）＋ ken_all | `scripts/build_extinct_municipalities.py` |
| 地理データ | geolonia 住所データ | `scripts/build_geocoding_index.py` |

日本郵便のデータは毎月更新される。最新化は `python scripts/build_postal_master.py`。

**生成物を更新したら `index.html` の `DATA_VERSION` を必ず上げる。** ブラウザが約9MBの旧JSONをキャッシュし続け、更新が反映されない。

## 制約

- 番地レベルのジオコーディングは行わない（町域重心まで）
- 建物名・部屋番号は住所本体と分離するのみで、正規化しない
- ローカルのHTMLを直接開くと `fetch` が使えずマスターを読めない。公開URL上で実行する
